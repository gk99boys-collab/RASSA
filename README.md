# وب‌سایت معرفی تیم رَسا (Rasa Team Site)

وب‌سایت تک‌صفحه‌ای، فارسی (RTL) و موبایل‌محور برای معرفی تیم نرم‌افزاری **«رَسا»** در **هشتمین رویداد ملی تولید محتوای دیجیتال بسیج** (رشته‌ی نرم‌افزارهای ویژه تلفن همراه)، با طراحی نئوبروتالیسم و المان‌های پیکسلی هماهنگ با هویت بصری رویداد.

## امکانات و پشته فنی

- **Vite + React 19 + TypeScript + Tailwind CSS v4**
- **هویت بصری رسمی**: لوگوی رسمی تیم **رَسا** (`public/logo-rasa.png` و `public/logo-rasa-mark.png`)، لوگوی رسمی **هشتمین رویداد ملی تولید محتوای دیجیتال بسیج** (`public/logo-event.png`) و آیکون تب و نشانک از همان لوگوی رویداد (`favicon.ico`، `favicon.png` و `event-touch.png`)
- **صفحهٔ معرفی در سبک گرافیکی رویداد**: پوستر قرمز با دو نشان رسمی، کارت معرفی سه‌گامی، فهرست و شناسنامهٔ تعاملی اعضا و کارنامهٔ تیم. بخش‌ها با اسکرول طبیعی و پیوندهای `#about`، `#members`، `#honors` و `#projects` در دسترس‌اند.
- **ورق‌زدن با اسکرول**: بخش اعضا در حالت پویا، تا مرور آخرین کارت زیر سربرگ ثابت می‌ماند. در صفحه‌های کم‌ارتفاع، عنوان یا فهرست کنار می‌رود تا خود کارت کامل دیده شود. با رسیدن به آخرین ایستگاه، اسکرول بعدی بلافاصله صفحه را ادامه می‌دهد. برگشت، لمس، دکمه‌های قبلی/بعدی و «عبور از اعضا» در دسترس‌اند. در حالت آرام یا وقتی کارت در ارتفاع صفحه جا نشود، پیمایش عادی است.
- **میز مدیریت خصوصی**: [ورود با لینک خصوصی و رمز چهاررقمی](./supabase/MEMBER_DESK.md)، بدون ثبت‌نام یا UID. افزودن، ویرایش و حذف فقط با نشست تأییدشدهٔ سرور.
- **کارت اختصاصی اعضا**: هر کارت، قاب عکس شخص و یک [تصویرسازی اختصاصی کارگاه](./public/member-covers/README.md) دارد. سربرگ‌ها با هوش مصنوعی ساخته شده‌اند، اما برای افراد چهره تولید نشده است. مدیر می‌تواند برای هر عضو جداگانه یک لوگو/عکس و یک کاور بارگذاری کند. عکس قبلی (`members.photo_url`)، حروف اول نام و تصویرسازی نقش، پشتیبان‌اند. صندلی پنجم تا زمان معرفی، جلد خنثی و نشان قفل دارد.
- **موشن‌پوستر سه‌قابی**: «می‌رسیم» با حرکت نشان پیکسلی روی مدار، «می‌سازیم» با ساخت اپلیکیشن و «می‌درخشیم» با مهر رتبهٔ اول. دکمهٔ مکث، پخش را در همان لحظه نگه می‌دارد. انتخاب یکی از سه قاب، پوستر را روی آن قاب ثابت می‌کند؛ برای ادامه دکمهٔ پخش را بزنید. پوسترِ در حال پخش به حرکت ماوس نیز عمق می‌دهد.
- **حرکت صفحه**: اینتروی کوتاه و قابل رد کردن (یک‌بار در هر تب)، ورود هماهنگ تیتر فارسی، خط پیشرفت مطالعه، ورق‌خوردن شناسنامهٔ اعضا، انتخاب فنری با `layoutId` و شمارنده‌های غلتکی فارسی.
- **حالت آرام**: دکمهٔ «حالت پویا» بالای هیرو تمام حرکت‌های تزئینی را خاموش می‌کند و انتخاب در مرورگر حفظ می‌شود. تنظیم کاهش حرکت دستگاه اولویت دارد؛ حتی در حالت آرام هر سه قاب و همهٔ پروفایل‌ها با لمس یا صفحه‌کلید قابل انتخاب‌اند. فهرست اعضا از کلیدهای بالا/پایین (چپ/راست در موبایل)، `Home` و `End` پشتیبانی می‌کند.
- **فونت کلمه با ارقام فارسی (Kalameh FaNum)** در پنج وزن محلی برای متن و تیترها؛ وزیرمتن پشتیبان است. [فایل‌ها و وزن‌ها](./public/fonts/README.md) بدون وابستگی به CDN خارجی ارائه می‌شوند.
- **موسیقی خراسانی**: آهنگ `public/music/Khorasani.mp3` هنگام ورود به‌صورت تکراری پخش می‌شود؛ اگر مرورگر اجازه ندهد، با اولین تعامل مجاز شروع می‌شود. پخش/مکث در سربرگ در دسترس است. [راهنمای بارگذاری و رفتار مرورگر](./public/music/README.md)
- **پروژه‌های تیم**: بخش «پروژه‌ها» (`src/components/Projects.tsx`) کارهای منتشرشدهٔ تیم را — از جمله وب‌سایت خوسف (رتبهٔ اول دورهٔ هفتم) — نمایش می‌دهد و لینک‌ها در `src/data/projects.ts` قابل ویرایش و افزودن‌اند.
- **Supabase JS Client** با کلید عمومی (`anon`)، جدول‌های فقط‌خواندنی برای مراجعه‌کنندگان و رویه‌های مجزای مجوزدار برای میز مدیریت + داده‌ی پشتیبان محلی (Fallback) و اسکلت بارگذاری نئوبروتالیستی

پوستر و خط زمانش از یک `MotionValue` مشترک استفاده می‌کنند، نه بازترسیم React در هر فریم. با خروج پوستر از دید یا پنهان شدن تب، ساعت پخش متوقف می‌شود و با بازگشت از همان‌جا ادامه می‌یابد.

## افزودن پروژه به بخش پروژه‌ها

هر پروژه یک آیتم در `src/data/projects.ts` است: `{ id, kicker, title, description, url, cta, badge, context }`. با افزودن یک آیتم جدید، کارتش در بخش «پروژه‌ها» (زیر پیوند «پروژه‌ها» در سربرگ) به‌طور خودکار ظاهر می‌شود و با لمس آن در یک تب جدید باز می‌شود. متن `badge` مهر ویژهٔ رتبهٔ تیم را نمایش می‌دهد و `context` زمینهٔ زمانی پروژه را (مثلاً «سال گذشته — دورهٔ هفتم»).

## متغیرهای محیطی (Environment Variables)

برای همین سایت نیازی به تنظیم دستی نیست. برای اتصال اختیاری در زمان بیلد، این دو متغیر عمومی را در `.env` محلی یا سرویس میزبانی تنظیم کنید:

```env
VITE_SUPABASE_URL=https://<your-project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-public-anon-key>
```

> هرگز کلید `service_role` را در فرانت‌اند یا مخزن گیت قرار ندهید. بدون متغیرهای بیلد، سایت تنظیم عمومی اتصال را از تابع `rassa-public-config` پروژه می‌خواند. اگر ارتباط برقرار نشود، سایت به‌طور خودکار با داده‌ی پشتیبان محلی (`src/data/fallbackData.ts`) به‌صورت کامل نمایش داده می‌شود.

## ویرایش اطلاعات و آپلود عکس اعضا در Supabase

جداول و باکت پروژه از قبل آماده‌اند؛ برای نصب یا انتشار سایت نیازی به اجرای SQL نیست. فایل [`supabase/schema.sql`](./supabase/schema.sql) صرفاً مرجع اسکیما و داده‌های اولیه است.

### ۱. ویرایش اطلاعات تیم (`public.team`)
در داشبورد Supabase به بخش **Table Editor → `team`** بروید و ستون‌های `name`، `tagline`، `description`، `achievement_text` و `links` را ویرایش کنید.

ستون `links` از هر دو فرمت JSON پشتیبانی می‌کند:
```json
[
  { "label": "گیت‌هاب", "url": "https://github.com/...", "type": "github" },
  { "label": "ایتا", "url": "https://eitaa.com/...", "type": "eitaa" }
]
```
یا:
```json
{
  "github": "https://github.com/...",
  "telegram": "https://t.me/..."
}
```

### ۲. آپلود مستقیم لوگو/عکس و کاور هر عضو
1. با لینک خصوصی و رمز وارد میز مدیریت شوید. عضو را انتخاب کنید یا «عضو جدید» را بزنید.
2. در بخش «تصاویر عضو»، برای **لوگو یا عکس عضو** و **کاور کارت عضو** دو دکمهٔ «انتخاب فایل» وجود دارد. یک یا هر دو فایل را از گوشی یا رایانه انتخاب کنید؛ پیش‌نمایش بدون ارسال فایل نمایش داده می‌شود. فرمت‌های JPG، PNG و WebP تا ۵ مگابایت پذیرفته می‌شوند. برای کاور، تصویر افقی عریض مناسب‌تر است.
3. «ثبت عضو» یا «ذخیرهٔ تغییرات» را بزنید. پس از تأیید، با تازه‌کردن سایت عمومی عکس را در قاب عضو و کاور را در بالای همان کارت می‌بینید. انتخاب‌نکردن فایل جدید، تصویر ذخیره‌شده را تغییر نمی‌دهد. برای برداشتن فقط یکی از تصاویر، «بازگشت به پیش‌فرض» همان قسمت را بزنید و ذخیره کنید.

این دو فایل ربطی به لوگوی تیم یا آیکون رویداد ندارند. برای استفاده از روش قبلی، در بخش اختیاری نشانی عکس، مسیر `member-photos` یا لینک عمومی را وارد کنید.

### ۳. جایگزینی کارت معمایی عضو پنجم (`sort_order = 5`)
در جدول `members` ردیف `sort_order = 5` (که فعلاً `به‌زودی...` است) را ویرایش کنید و نام واقعی، نقش (`role`)، مهارت‌ها (`skills`)، بیوگرافی (`bio`)، `photo_url` و `links` عضو پنجم را وارد کنید. به‌محض تغییر نام از `به‌زودی...`، کارت قفل‌شده به‌طور خودکار و بدون نیاز به تغییر کد به کارت عادی عضو تبدیل می‌شود.

## استقرار (Deployment)

پروژه کاملاً استاتیک است (`base: './'`) و روی هر سرویسی قابل استقرار است:

- **Vercel / Netlify**: مخزن را متصل کنید، دستور ساخت را `npm run build` و پوشه‌ی خروجی را `dist` بگذارید؛ تنظیم متغیرهای اتصال برای این پروژه اختیاری است.
- **GitHub Pages**: با مرج روی `main`، گردش‌کار [deploy.yml](./.github/workflows/deploy.yml) سایت را روی [نشانی رَسا](https://gk99boys-collab.github.io/RASSA/) منتشر می‌کند. دو متغیر عمومی `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` در **Settings → Secrets and variables → Actions** هنگام بیلد خوانده می‌شوند. اگر تنظیم نشده باشند، کلید عمومی هنگام اجرا از پروژه خوانده می‌شود. تغییر اطلاعات جداول نیاز به بیلد ندارد؛ تغییر متغیرهای محیطی نیاز به بیلد مجدد دارد.

## آزمون رابط کاربری

```bash
npm ci
npx playwright install chromium
npm run test:e2e
npm run test:policy
```

آزمون‌ها نسخهٔ تولید را زیر مسیر `/RASSA/` با پاسخ‌های محلی شبیه‌سازی‌شده بررسی می‌کنند: بارگذاری و قطع دسترسی، باز شدن صندلی پنجم با تغییر نام، عکس و پیوندها، تب‌های راست‌به‌چپ، اینتروی قابل رد کردن و نمایش موبایل. پخش و مکث واقعی پوستر، انتخاب قاب با لمس، توقف خارج از دید، حالت آرام و فرود دقیق ارقام نیز آزمایش می‌شوند. این آزمون‌ها روی اعضای واقعی چیزی نمی‌نویسند. آزمون PR در `verify-member-media.yml` فایل را با بلیت آزمایشی به یک نمونهٔ محلی و موقت Supabase می‌فرستد، هر دو عکس را از نشانی عمومی می‌خواند و محدودیت‌های نوشتن و حذف را بررسی می‌کند.
